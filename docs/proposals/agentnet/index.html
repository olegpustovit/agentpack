Proposed architecture
One binary. One node per user. One owner per terminal.

 
Merge Agentnet into Agentpack as its network and desktop interface. Every agent launch automatically starts or joins a node. The existing Agentpack launch pipeline still prepares the environment. A session worker owns the PTY so the CLI and browser attach to the same process.

 
Confirmed preferences: start or join automatically on every agent launch; automatically restart affected agents after package installation; keep CLI sessions running when sharing stops; authorize your own Tailscale identity plus explicitly allowed servers. All commands and configuration below are proposed interfaces, not commands already shipped.

 
 

  
Terminal behavior
  • Raw PTY bytes travel in binary WebSocket frames. No vendor JSON adapters, prompt bus, transcript parsing, or injected collaboration MCP.
  • The local terminal owns input and size initially. Browser control requires an explicit handoff. Observers never resize the shared terminal. An ownership epoch rejects delayed input after a handoff.
  • Control operations such as resize, attach, and stop use a small authenticated API. “No JSON message passing” means no agent-message bus; metadata still needs ordinary structured HTTP.
  • Bounded per-observer queues prevent a slow browser from stalling the agent. Disconnect lagging observers and clearly report missing history. Never display a replay gap as a complete terminal screen.
  • Use xterm.js for ANSI, alternate screen, Unicode and keyboard behavior. Clipboard writes, clickable links, and terminal escape sequences receive explicit security policies.

  
Transparent lifecycle
  • One node per OS user and AGENTPACK_HOME; concurrent first launches serialize startup with the existing file lock dependency.
  • A small worker per session owns PTY, process group, attachment lease and restart state. The worker starts through the CLI and survives a node restart; all workers appear in node status.
  • Every launch prints its session ID, access URL and stop command on stderr. No shell profile edits, root service, PATH edits, firewall changes, or Tailscale login changes.
  • Preserve noninteractive pipes and exact exit codes. Headless commands register presence but retain their native stdio; browser input is unavailable for those runs.
  • If node startup or discovery fails, ordinary local launch still works with one actionable warning. A worker failure cannot silently relaunch an agent and duplicate work.

Install once, restart exactly what changed

 
 
  • The owner invokes the existing add/resolve/sync services for a registered environment ID. Browser requests cannot nominate arbitrary filesystem paths or shell commands. Filesystem dependencies resolve on the owner host.
  • Compare effective staged content per harness and mode. A package disabled in a session’s mode does not restart that session. Shared definition roots affect all their workspaces; identical repository names on another machine do not imply shared configuration.
  • Before any agent is stopped, finish fetching, integrity checking and staging. Existing generation paths and leases remain valid. If the current add implementation writes manifest or lock before a staging failure, report that partial state; do not claim transactional rollback until implemented and tested.
  • Serialize stop/restart per session and use an operation ID so network retries cannot restart twice. Wait for the old process group to exit, run cleanup, then re-enter the normal launch pipeline with fresh staging. Do not replay a stale CODEX_HOME or expired proxy URL.
  • Preserve the session attachment and record a generation boundary. Clear the emulator at a new process boundary. Resume a conversation only using a verified harness-specific resume recipe; otherwise the new agent starts a fresh conversation, visibly labeled.
  • Failed replacement starts stay failed with their error visible; no restart storm. Package changes made through the CLI must trigger the same invalidation path, with a fingerprint check on reconnect as a backstop.

 

 
Recent folders, without repository provisioning
Record successfully launched workspaces on their owner node: canonical workspace path, definition-root reference, harness, mode, and last-used time. Keep a small bounded history in the private Agentpack home. Never retain environment secrets, terminal output, or arbitrary command-line arguments in this list.
The UI offers Open session for a live session and Start fresh for a recent folder. Starting fresh creates a new session ID and goes through normal staging, validation and launch; it does not imply conversation resume. The browser selects a recorded folder; the owner checks that its path appears in local recent history. The owner revalidates the directory and authorization before launch. Missing folders are labeled unavailable; a Forget folder action removes only the history entry.
Remote fresh starts use the same session worker but need an independent OS service scope so stopping the gateway leaves them alive. Test this under systemd and launchd, not only with a detached subprocess. Repository clone, checkout, credentials for new repositories and arbitrary remote command execution stay out of this feature.

Remote access is enabled explicitly once per machine. Own untagged Tailscale identity is allowed by default; tagged servers and other identities need explicit permission.
agentpack gateway sharing on

agentpack gateway sharing allow nStableNodeID

Private configuration and state live under $AGENTPACK_HOME/network/. The peer listener binds only a Tailscale IP on port 7421. A fixed public HTTPS origin is configured separately; no arbitrary peer URL is accepted. The setup token and password hash never enter frontend assets or command-line arguments.

 
Linux, macOS and Windows service behavior
Linux uses a systemd user unit with KillMode=process. macOS uses a launchd user agent with AbandonProcessGroup. Windows uses a limited current-user Scheduled Task and a WMI bootstrap outside its process job. Services capture the executable path and Agentpack home, and respect a persistent stop marker at login.
Install is explicit. No shell-profile or persistent PATH edits, system-wide lingering, or root privileges are needed for user services. Uninstall removes the service definition and preserves packages, credentials and session data. The Oracle deployment uses an unprivileged persistent user service and preserves unrelated Caddy sites.
Template and mocked-command checks exist. Native macOS/Windows lifecycle and two-host survival checks remain required before declaring runtime support complete.

Public gateway and MCP
The requested public URL is https://agentpack.microapps.space, deployed to oracle-vm. Bootstrap uses a one-time token obtained over the machine console or SSH; the first anonymous visitor cannot claim the root account. HTTPS terminates at the existing reverse proxy, with the backend bound to loopback.
The MCP interface exposes authorized node, session and package operations for ChatGPT, Grok and other clients. OAuth metadata, dynamic client registration, PKCE, consent, refresh and revocation follow the sibling email MCP server's pattern. MCP operates the same owned sessions and trust boundaries as the browser; it is not an agent-to-agent prompt bus. Real client connection checks remain part of delivery validation.

Regression checklist and measurable acceptance
  • All six harness commands retain passthrough arguments, CWD, environment binding, strict-external policy and native login/logout behavior. GUI-only launchers appear as presence; do not claim an interactive terminal where the vendor has none.
  • No unchanged lock rewrites, unrequested pin movement, softened integrity errors, duplicated skills, changed overlay ownership, or leaked credentials.
  • Each session runs one child generation at a time. The node never kills a process it does not own. Stop and restart operate on the owned process group, with a bounded graceful exit.
  • Suggested budgets to validate, not measured results: warm attach overhead under 100 ms; reachable peer appears within 10 s; observer memory bounded at 1 MiB per attachment plus an 8 MiB per-session replay ring. Record measured overhead before setting CI thresholds.
  • No account quota or model prompt requirement in release gates. Use deterministic fake agents for terminal tests, then optional manual real-agent smoke tests.
  • Packaging uses one Go module and the current binary. Frontend build is required for release asset freshness, not for every backend-only test invocation.





Decisions
The choices that change behavior
The launch, restart, access, deployment, MCP, design and platform decisions below are confirmed. Remaining work is validation, not an open product-choice questionnaire.

 

 
Automatic launch registration
Confirmed: every agent launch starts or joins the node. No one-time opt-in is required. Explicitly stopping sharing is a durable opt-out until re-enabled.

 
Automatic package restart
Confirmed: install then automatically restart affected agents. The install review names interruptions. Conversation continuity cannot be assumed across vendors.

 
Stop behavior
Confirmed: stop sharing and keep existing CLI sessions running. A separate action stops agents. Session workers must survive the gateway service stopping.

 

 
Who can control sessions?
Confirmed: personal setup. Your Tailscale identity and explicitly allowed servers can participate. Other reachable tailnet members do not automatically gain terminal control.

 
Existing sessions and recent folders
Confirmed: focus on opening existing sessions. Add a small Recent folders list so an agent can start fresh in a previously used directory. Remote repository cloning is deferred as unnecessary scope.
Recent folders is part of the delivery plan; its launch flow is not simulated in this prototype.

 
Public deployment and root account
Confirmed: agentpack deploy targets oracle-vm and https://agentpack.microapps.space. Create the application root account once using a private setup token from the server console. The gateway service runs as an unprivileged OS user.

 
MCP and shared design
Confirmed: expose authenticated Streamable HTTP MCP to ChatGPT, Grok and other clients, using the email MCP project's OAuth/PKCE/consent model. Reuse Agentnet's macOS design tokens across login, sessions, packages and settings.

 
Windows and PowerShell
Confirmed: Windows is in scope, including ConPTY sharing, PowerShell deployment and native service commands. Passing a cross-build alone does not verify Windows runtime behavior.
